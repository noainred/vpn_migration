켜짐: 스캔을 멈췄다 다시 시작해도 누적을 이어서 기록. 꺼짐: 매번 새로 시작.

1. 파일 업로드

파일을 끌어다 놓거나 클릭하여 선택

tshark 캡처 CSV · 사전 집계 report.json · tinc 로그
.csv .json .log .txt — 다중 선택 가능

수십 GB 캡처는 서버에서 스트리밍 CLI로 처리 후 결과 JSON만 업로드하세요:
tinc-flow-analyzer -j 4 -f json -o report.json capture.csv

    고급 옵션 — tinc 로그 전용 (서브넷 덤프 · 호스트 매핑 · 연도)

    📡 실시간 캡처 — 서버에서 tshark 실행

    서버를 --enable-capture 로 실행해야 하며, 해당 호스트에 tshark와 캡처 권한이 필요합니다. 진짜 종단 간 IP는 VPN 인터페이스(tun0)에서, 노드(엔드포인트) IP는 물리 NIC(ens192)에서 캡처됩니다.

    🖥 서버에서 직접 분석 — 대용량 캡처 · 다중 서버 통합

    서버에 저장된 캡처 CSV(.csv/.gz, 수십 GB)나 각 서버의 portal_data 디렉터리를 포탈이 스트리밍 단일 패스로 직접 분석합니다. 무거운 처리는 포탈과 분리된 별도 프로세스에서 수행되어 포탈을 멈추지 않으며, 포탈을 재시작/업그레이드해도 작업은 계속됩니다. 결과는 완료 시 아래 결과 화면에 자동으로 표시됩니다.

    필터 / 제외 옵션 — 조건에 맞는 데이터를 분석에서 제외하고 표시 개수 제한
    선택하면 값이 채워집니다 · 분석은 [분석 시작] 클릭
    제외 프로토콜:
    0 = 무제한

    제외 = 분석에서 빼는 조건. 원본 CSV는 패킷 단위로 정확히 제외, 머지(집계본)는 통신쌍/서비스 단위로 제외합니다. 옵션은 분석 시작 시 자동 저장되어 다음에 다시 불러옵니다.

    보안: 포탈 프로세스 권한으로 서버 파일을 읽습니다. 기본 바인딩은 127.0.0.1(로컬 전용)이며, 외부에 노출할 경우 접근 제어를 두세요. 병렬 워커는 입력을 정확한 줄 경계로 분할 후 병합합니다(순차 결과와 비트 동일).

    🔎 단계 필터 (드릴다운) 결과를 1차 → 2차 → 3차… 순서로 좁혀 봅니다. 분석을 다시 돌리지 않고 즉시 적용. 포함만/제외 선택.
